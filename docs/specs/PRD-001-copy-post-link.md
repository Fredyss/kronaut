# PRD-001: Copy link on the post detail page

Status: draft
Owner: Frederik Schlentc
Date: 2026-11-16

## Goal

Someone who has published a post wants its public address on the social platform, to paste into a chat, a newsletter or a report. Today the post detail page only offers "View post", so they open the post in a new tab and copy the address from the browser. After this change, each published destination on the post detail page has a "Copy link" button that puts that address on the clipboard in one click.

## Scope

**In:**

- A "Copy link" button in each destination row of the post detail page (`/posts/$postId`), beside the existing "View post" link.
- A toast that confirms the copy, and a toast when the copy fails.
- Three new messages in en, sk and cs.

**Out (non-goals):**

- Copying the address of the post page in Kronaut.
- A copy button in the inbox row, the calendar, the post preview or any other screen that shows "View post".
- A copy button for short links or for the long links inside the post text.
- Any change to the copied address: no shortening, no UTM parameters, no trimming.
- A new shared component in `packages/ui` or `apps/web/src/base/ui/`.
- Any server, contract, SDK or database change.

## Behaviour

### Normal path

- A destination row shows "Copy link" exactly when it shows "View post": when `httpsUrl(destination.remoteUrl)` is not `null`. The destination's state plays no part.
- The button sits directly after the "View post" link, in the same wrapping line of the row.
- A click writes the value of `httpsUrl(destination.remoteUrl)`, unchanged, to the clipboard as plain text through `navigator.clipboard.writeText`.
- When the write resolves, the page shows the toast "Link copied." in the default variant.
- The button stays enabled and keeps its label before, during and after the copy.
- The value is read at click time, so a row whose address changed after a refetch copies the new one.

### Edge cases

| Case | Expected result |
| --- | --- |
| Empty input: `remoteUrl` is `null` | No button and no "View post" link |
| `remoteUrl` is not an https URL (`http:`, `javascript:`, unparseable) | No button and no "View post" link |
| Several destinations with an address | One button per row; each copies its own row's address |
| Duplicate: the same button clicked again | The address is written again and a second toast appears. No debounce |
| Too large | Not applicable; the address is copied whatever its length |
| Concurrent: the post is refetched while a copy is in flight | The copy finishes with the address read at click time |
| Offline | Works; copying needs no network |
| Unauthorised | Not applicable: everyone who can open the page already sees the address in "View post", and no request is made |
| `navigator.clipboard` is missing (page not in a secure context) | The button is still shown; a click shows the failure toast |
| The browser rejects the write (permission denied, document not focused) | The failure toast |

### Errors

| Failure | What the user sees | What the system does |
| --- | --- | --- |
| `navigator.clipboard` is undefined | Toast "Couldn't copy the link." in the `destructive` variant | Nothing else: no retry, no fallback copy method, no log, no thrown error |
| `writeText` rejects | The same toast | The rejection is caught; nothing else |

## Data

None. No entity, field, constraint or migration changes.

## Interfaces

- No endpoint, event, command or package export is added or changed.
- One new component, internal to the `post-page` feature, in `apps/web/src/pages/post-page/copy-link.tsx`:

  ```ts
  export function CopyLink(props: { readonly url: string }): ReactNode;
  ```

  `url` is the already-validated https address. The component renders the button and owns the copy and both toasts.
- `DestinationRow` in `post-page.tsx` renders `<CopyLink url={link} />` inside the existing `link === null ? null : …` branch, after the anchor.
- `post-page.tsx` has 296 lines, 283 as Biome counts them against its limit of 300. The component lives in its own file, so the page file grows only by the import and the element.

## UI

- **Element:** a native `<button type="button">`, not the `Button` primitive, with the classes `text-foreground underline underline-offset-4`, so it reads as a sibling of "View post". No icon.
- **States:** one state only. No loading, pressed or disabled state, and no label change.
- **Accessible name:** the visible label. No `aria-label`.
- **Toasts:** through `toast` from `@kronaut/ui`; the failure uses the `'destructive'` variant.
- **Copy**, added to `packages/i18n/messages/{en,sk,cs}.json` after `post_view`, with the compiled catalogs regenerated by `pnpm --filter @kronaut/i18n i18n`:

  | Key | en | sk | cs |
  | --- | --- | --- | --- |
  | `post_copy_link` | Copy link | Kopírovať odkaz | Kopírovat odkaz |
  | `post_link_copied` | Link copied. | Odkaz je skopírovaný. | Odkaz je zkopírovaný. |
  | `post_link_copy_failed` | Couldn't copy the link. | Odkaz sa nepodarilo skopírovať. | Odkaz se nepodařilo zkopírovat. |

## Permissions and security

- Every role that can open the post page sees the button. It reveals nothing the "View post" link doesn't already show.
- The only input is `destination.remoteUrl`, which comes from the provider through the API. It reaches the clipboard only after `httpsUrl` accepted it, the same gate as the anchor's `href`. The value is never rendered as HTML and never put into a URL the app navigates to.
- No request leaves the browser.

## Limits

None. The button adds no request and no polling.

## Rollout

No flag and no ordering. The change is additive and ships in one PR.

## Testing

In `apps/web/src/pages/post-page/post-page.test.tsx`, rendering the app as the existing test does, with `navigator.clipboard` stubbed:

1. The fixture post (one https destination, one `javascript:` destination) shows exactly one "Copy link" button.
2. A click calls `writeText` once with `https://bsky.app/profile/ada/post/1` and shows "Link copied.".
3. With `writeText` rejecting, a click shows "Couldn't copy the link." and nothing is thrown.
4. With `navigator.clipboard` undefined, a click shows "Couldn't copy the link.".

Cases 1 and 2 matter most. `pnpm check` must pass, including Biome's file and function size limits. The bundle budgets, which CI runs separately as `pnpm --filter @kronaut/web size`, must hold too.

## Technology

None. `navigator.clipboard` is a browser API; no dependency is added.

## Defaults for the unforeseen

- Follow the "View post" link in `post-page.tsx` for placement, visibility and styling.
- Follow `apps/web/src/actions/post-actions/delete-dialog.tsx` and `duplicate.ts` for how toasts are raised.
- Prefer the smaller change: no new shared component, no new feature import, no new dependency.
- Prefer showing nothing over copying a value that `httpsUrl` did not accept.
- If the change would need a line in `tools/lint/feature-imports.json`, a higher bundle budget or any protected path, stop and report instead of working around it.

## Decisions

| Decision | Reason |
| --- | --- |
| The button copies the destination's platform address, not the Kronaut page address | It is the link people paste elsewhere; the Kronaut address is already in the address bar and needs a login to open |
| One button per destination row, visible exactly when "View post" is | A post has one address per channel, and one rule for both controls keeps them from drifting apart |
| Confirmation by toast, not by a changing label | It is the pattern the app already uses, it is announced to screen readers, and it needs no per-button state |
| The button stays visible when the clipboard API is missing, and fails with the toast | One failure path instead of two; the supported setups serve the app over https or localhost, where the API exists |
| No fallback copy method (`document.execCommand`) | Deprecated, and only reachable outside a secure context |
| A native text button styled like the link, without an icon | It sits in a line of text links; the `Button` primitive would outweigh "View post" |
| The label is the same on every row, with no channel name in it | "View post" does the same, and the row already names the channel |
| The component lives in `pages/post-page/copy-link.tsx` | Code stays with its only user, and `post-page.tsx` is already close to the 300-line limit |
| Inbox row and short links are out of scope | The request names the post detail page; each is a separate, small follow-up |
| Tests extend the page test and add no component test file | The page test already renders the app with its `Toaster`, so it covers the button, the copy and the toast through the real seam |
