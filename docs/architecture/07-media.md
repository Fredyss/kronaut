# Media

- **v1 hosting:** `./data/media`, served by `--role=media` on `media.<domain>` through the tunnel. CF Access is bypassed for **that hostname only**, never by path on the app.
- **Public hostname required:**
  - IG/Threads/TikTok fetch media from it, OAuth callbacks need it, and Bluesky's confidential client publishes its client-metadata URL on it (ADR-0035).
  - Setup checks reachability before connecting the first channel.
- **Signed URLs:** `?exp=&sig=` HMAC.
  - **Signed at attempt time**, with TTL ~1 h for images and ~6 h for video; re-signed on each retry.
  - IG/Threads containers live 24 h.
  - Meta/TikTok fetch windows are measured in Phase 0.
- **TikTok:**
  - `PULL_FROM_URL` from a **verified domain** (required for photo posts). `FILE_UPLOAD` is not used from servers.
  - The `init` call is the public step. SELF_ONLY posts never return a post id (`verify.mode=none`).
- **Video** (ADR-0054): chunked upload in 8 MiB parts, at most 300 MB; a background job converts each video with ffmpeg into one H.264/AAC MP4 master that every network publishes unchanged. Range requests are served for video.
- **Upload** (ADR-0054): images are one JSON request. A video goes through `POST …/media/uploads`, one raw `PUT …/media/:mediaId/parts/:n` per 8 MiB part and `POST …/media/:mediaId/complete`, which queues the conversion. Parts are staged as files under `<data>/media/.staging/<key>/`, and an unfinished upload expires after 24 h.
- **Masters and renditions:**
  - Masters are immutable once ready and identified by sha256, which approval hashes reference.
  - Per-provider renditions (resize, transcode, crop in per-mille) are derived and cached.
- **GC:**
  - originals 30 d after their last reference
  - renditions 7 d after last use
  - unfinished uploads 24 h after they started, staged parts included
  - Thumbnails at 256/768 px AVIF/WebP are kept for the library.
  - Deleted assets: the job re-checks inside `withTenant()` that no `item_media` or `destination_media` row references the asset, then removes the original, its renditions and the row. A re-upload of the same file within the 30 days revives the soft-deleted row instead.
- **Library** (Phase 1.1):
  - Lists the workspace's assets with `in_library`, not deleted and not `uploading`, newest first (keyset on the uuidv7 `id`), filterable by `kind`.
  - Editing sets the asset's default `alt_text`. Alt text already copied into a post's `item_media` doesn't change.
  - Usage lists the posts whose items or destinations reference the asset.
  - Delete is soft (`deleted_at = now()`) and refused with 409 `media_in_use` while any `item_media` or `destination_media` row references the asset. The GC purges it 30 days later.
  - The AI label can be cleared only by a member in a session, never by an API key or agent. A grant setting or confirming the label (upload, mark, or a duplicate of the asset) sets `media_assets.ai_locked`, and a locked label can't be cleared: agent-generated media stay labelled.
  - Usage shows post text, so it needs `posts:read` as well as `media:read`.
  - Edit, clear and delete touch only library assets (ready or processing, not a duplicate); anything else is 404.
- **SaaS:** R2 + a Cloudflare Worker with the identical HMAC scheme. Uploads go direct from the browser via presigned multipart PUT.
