# Frontend

- **New create and edit flows open in a dialog over the current page,** so the user keeps their place. The full-page composer remains for the flows listed in [Code structure](13-code-structure.md).
- **Post editor with variants (ADR-0033):**
  - The default variant applies to all destinations.
  - "Customize for <network/account>" forks a full variant, with its own item list, which shows an "inherited / customized" badge and can be reset.
- **Live validation strip** from the shared manifest ("X 291/280", "IG Reel needs 9:16, 3–90 s", Bluesky graphemes + bytes):
  - Media is checked in a Web Worker (`createImageBitmap`, mediabunny) *before* upload.
  - Schedule stays disabled until everything is valid, and each error comes with a fix action.
  - "Add to queue" sits next to ASAP and a fixed time. It shows each selected channel's next free slot, and is disabled with the reason when a channel has no slots. Each channel's queue is edited from the channel list.
  - "Repeat" sits under a fixed time: presets only (daily, weekly on days, monthly on a day, every N, end never/on a date/after N). The post page shows the series, its next time and a stop action.
  - The post page has an "Evergreen" switch (add to or remove from the pool) and lists its recent copies. The queue editor says that free slots are filled from the pool 24 h ahead.
  - The post page shows each published destination's latest counts and when they were read; a missing value shows as a dash, never 0. The channel page shows the follower count and its change over 30 days, and for a Meta channel connected without its insight scope, a line that reconnecting adds insights.
- **Previews** are React components per archetype (short-feed, pro-feed, media-grid, vertical-video, chat, article):
  - They use real truncation cutoffs and crop overlays.
  - Golden tests per network keep preview == published.
  - MVP: line clamps approximate the in-feed cutoff (pro-feed 3 lines, media-grid 2 lines); exact per-network cutoffs come later.
- **Per-media alt text + AI label:**
  - IG `is_ai_generated`, TikTok `is_aigc`, X `made_with_ai`, YouTube `containsSyntheticMedia`.
  - The flag is sticky for agent-generated media.
  - Compose sets it per image as `aiGenerated` on the upload. The flag lives on the deduplicated `media_assets` row, so an upload can set it but never clear it; clearing belongs to the media library.
  - Of the shipped networks Instagram takes it (`is_ai_generated` on the single image, the carousel parent and the Reel), and so do Facebook Reels (`is_ai_generated` on `finish`). Threads, Facebook photo posts, Bluesky, Mastodon and LinkedIn have no such field (checked 2026-10-27; Threads re-checked 2026-10-28 against the `POST /{threads-user-id}/threads` reference).
- **Media library** (`/media`):
  - A grid of thumbnails, newest first, with an All / Images / Videos filter, loaded in pages.
  - The asset panel shows the preview, type, size, dimensions, duration and upload date. It edits the default alt text, clears the AI label where allowed, and lists the posts that use the asset, with links.
  - Delete is offered only for an unused asset; for a used one the panel shows how many posts use it.
- **Video ([ADR-0054](../adr/0054-video-pipeline.md)):**
  - A post content carries images or one video, never both; the media picker refuses the mix, other types and files over 300 MB.
  - The video belongs to the content, so a customized copy shares the default's video and its upload. A registry in the compose form holds each upload by a local id.
  - Picking a video starts the upload at once: the create call with an idempotency key, then 8 MiB parts in sequence (each retried up to 3 times on a network error or 5xx), then complete, then a poll every 3 s until the master is ready or rejected. A duplicate master switches to the kept asset. Removing the video or leaving compose aborts it; the server collects expired uploads.
  - The video row shows a muted preview, progress, processing, the duration, or the rejection reason, with Retry on an error, and an alt-text field as images have. The AI label is sent on create, or set later through `media.mark_ai`, and locks once the asset reports it.
  - A ready master is checked against the destination post type's `video` rules (mime, size, duration, aspect, and the frame rate and pixel count when the network sets them, as Mastodon instances do) with the `@kronaut/compose` issue codes. Instagram and Facebook publish it as `reel`, and Threads, Mastodon and LinkedIn as `video`, with the alt text; the other networks show video as not supported yet. Submitting waits until every used video is ready.
- **Platform-mandated UX:**
  - **TikTok:**
    - no default privacy, and interaction toggles default off
    - consent text and commercial-content disclosure
    - live `creator_info` before posting
  - **Pinterest:** a board picker and a video cover.
  - **X:** shows the cost per post (higher with a link) from the manifest `cost`.
- **Approval:**
  - Draft → In review → Approved → Scheduled.
  - An edit after approval resets it and shows a visible diff per destination.
  - A single-member workspace has self-approval on (visible in settings).
- **Needs action inbox:** unconfirmed / failed / blocked / awaiting_manual. "Send again" on unconfirmed requires ticking "this may post twice".
- **Calendar:**
  - week/month/list views
  - keyboard-first (j/k, n, e, d, ⇧-arrows, ⌘K)
  - the timezone shown on every time
  - optimistic drag-reschedule with an undo toast (re-approval warning when outside tolerance)
  - **Empty slot:** in week and day view, clicking (or Enter on) a free future slot opens the composer in a dialog over the calendar, with that date and time filled in, in the shown time zone. The dialog is the compose route's own form, loaded lazily; its state is in the URL (`?compose=new&at=…&tz=…`), so Back closes it and a reload reopens it. Closing with unsaved changes asks first, by Back, Escape, the close button or leaving the page; after saving or scheduling, the dialog closes and the calendar refreshes. Past slots aren't actionable.
  - **Post actions:** each calendar entry has an options button, shown on hover and focus and always on touch, with a menu (keyboard-operable, `menu` role):
    - **Open** → the post page;
    - **Stats** → the post page's analytics section (only when a destination is published);
    - **Edit** → the composer on this post (see "Editing a post"); only when it can be edited and the role allows it;
    - **Duplicate** → `POST …/duplicate`, then the composer on the copy;
    - **Preview** → a read-only dialog with the network preview the composer uses;
    - **Delete** → a confirm dialog; for a published post it says the post stays on the network and only leaves Kronaut. Hidden from roles without `posts:draft`.
- **Tags:** internal labels for finding and grouping posts, separate from hashtags and never published.
  - A tag has a name and one of eight colors. The color is only a hint, so the name is always available too (visible, or as the accessible name of a dot).
  - The composer and the post page pick tags, and can create one by typing a new name. The post page saves at once, in any state; the composer saves them with the post.
  - Calendar entries show up to three colored dots. The calendar filters by one tag, kept in the URL (`?tag=<id>`).
  - Settings → Tags renames, recolors and deletes them, for roles with `settings:write`, and shows how many posts use each. Deleting one asks first and says that count.
  - A duplicate, a series occurrence and an evergreen copy keep their source's tags.
  - A member restricted to some brands or channels sees only the tags used on posts they can see. The server refuses them a new tag, and the picker says why.
  - The composer saves tags first on a post it opened: a tag failure leaves the schedule alone. On a new post, a tag failure stops before scheduling, and the error says the post isn't scheduled yet. A post's tags only change if the user changed them in the form, so a save can't undo someone else's change.
- **Post page:** a post with a published destination shows its content read-only on the left and the network preview on the right, with the time, Stats, Duplicate and Delete below. A post that can still be edited shows an Edit button.
- **Editing a post:** the composer opens an existing post, at `/compose?post=<id>` or, over the calendar, in the dialog at `?compose=<id>`, from the options menu or the calendar's draft list. Changing the content, the channels or the time counts as unsaved changes.
  - **What can be edited:** a post whose destinations are all `draft`, `canceled` or `scheduled`, unless a canceled one is already live in part (the server would answer `destination_live`). A scheduled one needs a role with `posts:schedule`; otherwise `posts:draft` is enough.
  - **Canceled channels:** on a post with other destinations, a canceled one opens unticked, with a line naming it, so a save can't publish to it by accident. It stays canceled while the content and channels are unchanged. Saving a change removes it from the post; ticking it publishes to it again. A post that is canceled everywhere opens with all of them ticked.
  - **Nothing is lost:** the composer only opens a post it can show whole. It stays on the post page, with a line saying why, when a destination's channel isn't available, when one channel has two destinations, or when the content is a shape the composer can't show (media on a reply or comment, images next to a video, more than one video, the same media twice in one item). It also stays there when a stored publish type isn't the one the composer would choose, or a text has formatting the composer can't show. Destination settings and delivery mode the composer has no field for are sent back unchanged; settings belong to a publish type, so a media change that changes the type drops them.
  - **When:** a new choice, "Keep as draft", saves without scheduling; a new post offers it too. A post with no scheduled destination opens on it, so opening a draft to fix a typo can't publish it. A scheduled post opens on its fixed time. A post scheduled per destination opens on "Add to queue", with a line saying that saving takes the next free slots; where approval hides the queue, it opens on "Keep as draft". Repeat isn't offered: a series starts from a new post. On a series draft that still has its planned time, a line says the series schedules it at that time. A scheduled series post left on "Keep as draft" is skipped, because unscheduling clears its time: a line says so.
  - **Saving a scheduled post:** nothing changes on the server until Save. With unchanged content, a new fixed time goes through `reschedule`, which is atomic and keeps an approval, as dragging in the calendar does; if it's outside the approved schedule, the composer offers to request approval. With nothing changed, Save just closes. Otherwise the composer uploads new media, unschedules, saves and schedules again, in that order. If a later step fails, the post is a draft and the error says so; saving again continues from there.
  - **Channels that stop working:** a stored destination that becomes unusable while the post is open blocks Save until it's unticked, so a save never drops one silently.
  - **Conflicts:** an edit is based on the version that was opened. A `version_conflict` is never retried, because that would overwrite someone else's change: the composer says the post changed and offers to reload it. Unchanged content isn't sent.
  - **Approvals:** on a post in review, a line says that saving changed content withdraws the open request. The server voids it (04).
- **Autosave:** IndexedDB on every change (1 s debounce) + server revision; a multi-tab conflict banner.
- **Budgets** (gzipped, CI `size-limit`):
  - shell + calendar ≤ 150 KB
  - shell message catalogs (en, sk, cs) lazy, ≤ 12 KB for en and ≤ 13 KB for sk and cs; en is preloaded
  - each route catalog (per group and locale) ≤ 8 KB
  - CSS ≤ 25 KB
  - route chunks ≤ 40 KB
  - editor ≤ 130 KB (preloaded on hover)
  - emoji / cropper / AI / charts lazy, ≤ 40 KB each
  - INP < 100 ms with 500 posts/week
  - no prod source maps
- **Public review pages:** server-rendered escaped HTML, token → cookie exchange, `noindex`, near-zero JS.
- **Mobile and extension:**
  - A PWA for review/approve/status (Phase 3).
  - The extension does share-current-page only (WXT, later). It never reads third-party cookies.

## i18n: English, Slovak, Czech

- **Locales:**
  - `en` (source), `sk`, `cs`.
  - Stored per user (`users.locale`); the first visit falls back to `Accept-Language`.
  - No locale in URLs (the app is behind login). Public review pages use the viewer's `Accept-Language`.
- **Bundles:** only the active locale ships. Paraglide compiles one module per locale, so sk/cs add 0 KB to an English session. CI fails on a missing key in any locale.
- **Route catalogs:** the strings of a lazy route ship with that route, not with the shell.
  - Each group (`compose`, `calendar`, `media`, `inbox`, `settings`) is its own Paraglide project, `messages/<group>/{en,sk,cs}.json`, compiled to `src/paraglide-<group>/`, next to the shell project and the CLI one.
  - A group's catalog for the active locale loads with its route's chunk. A language switch loads every group already in use before the UI changes language, so a screen never mixes languages.
  - A message belongs to a group only when every use is inside that group's route modules. Anything shared, and every string the server uses (emails, API errors), stays in the shell catalog. A CI test enforces both.
- **Provider errors (ADR-0038):**
  - Shown as class codes with a localised message and fix action; raw provider text only under "Technical details".
  - CI fails if a mapped code is missing in any locale.
- **Plurals:**
  - sk/cs have `one / few / many / other` (1 príspevok, 2–4 príspevky, 5+ príspevkov).
  - Every count message uses plural variants resolved via `Intl.PluralRules`. `count === 1 ? … : …` in code is banned by GritQL.
- **Dates and numbers:**
  - Always `Intl` / Temporal `toLocaleString(locale)`, never hand-built formats.
  - The calendar week starts **Monday** for sk/cs (locale week info with a fallback table), on a 24 h clock.
- **Diacritics:**
  - Editor text is normalised to **NFC** before counting, serializing and hashing, so `č` = 1 character, not 2.
  - Without this, decomposed input pasted from macOS would break X/Bluesky limits and approval hashes.
  - Golden tests with sk/cs strings live in `@kronaut/compose`.
- **Length:**
  - sk/cs UI strings run ~20–35% longer than English, so there are no fixed-width buttons.
  - Playwright visual snapshots run in `cs` (the longest).
  - The `cs` visual snapshots are **not in yet**. Today `pnpm test:e2e` (`apps/server/e2e/`) runs a Chromium smoke suite against the real server, the built web app and a throwaway Postgres: setting the first password and signing in and out, the channel list, scheduling a post with Slovak diacritics, and the display name and language settings.
- **Server-side text:** notification emails and API error `message` use the same message catalog. The CLI has its own catalog in the same package (`messages/cli/`), so operator strings never ship to the browser. The machine-readable `code` stays English.
- **Translation flow:**
  - English source → AI draft → native review by you.
  - A glossary file (`post` = príspevok / příspěvek, `channel`, `schedule`, `approval`…) is kept in the repo so terminology stays consistent.
